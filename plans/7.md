# Plan for #7: Add readiness and liveness probes, run two replicas

## Goal
Configure the Kubernetes Deployment with two replicas plus readiness and liveness
probes against the existing `GET /health` endpoint, so traffic is sent only to
healthy pods and rolling deployment has redundancy. Application routes, response
shapes, and environment variables do not change.

## Dependencies (confirmed / plausible / open), each with change: yes | no
- **confirmed — change: yes:** `k8s/deployment.yaml` (`Deployment.spec.replicas`
  and the app container) is the direct change surface for replica count and
  HTTP probes.
- **confirmed — change: no:** `src/app.ts` already serves `GET /health` with a
  successful JSON response suitable for both probes.
- **confirmed — change: no:** `k8s/service.yaml` selects all `app=sandbox-app`
  pods and targets the named `http` port, so no Service change is required.
- **confirmed — change: no:** `.github/workflows/ci.yml` already waits for
  rollout, checks every pod's readiness/restarts, and runs the health smoke test.
- **confirmed — change: no:** `test/app.test.ts` and `e2e/smoke.spec.ts` already
  verify the health endpoint; no application behavior changes require new tests.
- **confirmed — change: no:** `src/config.ts`, `k8s/configmap.yaml`, and the
  README environment table have no new variable requirements.
- **plausible — change: no:** Pipeline rollout behavior should remain compatible
  with the existing resource requests and kind cluster; verify through CI.
- **open — change: no:** None; probe timing values can use conservative Kubernetes
  defaults appropriate for this immediately available health endpoint.

## Tests
- No unit or browser test changes expected.
- Run `npm run verify` to preserve application behavior.
- Validate the Kubernetes-only behavior in the pipeline: rollout, two ready pods,

No changes. The probes use container port `http`/3000 and do not read or add

## Risks

  the existing named HTTP port.
- Two pods increase resource consumption; retain the existing requests and limits.
- The pipeline's rollout, stability, smoke, and browser gates could fail if either
  replica is not Ready or the Service has no ready endpoints.
